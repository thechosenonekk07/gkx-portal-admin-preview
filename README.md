## 打开和恢复预览

双击本目录的 `启动本地预览.command`。启动器会更新预览文件、复用本项目正在运行的服务并打开固定地址。电脑重启或服务停止后，再次双击即可恢复。

双击 `停止本地预览.command` 只停止本项目服务。服务限定在本机 `127.0.0.1`，不对局域网开放。

终端也可在本目录执行：

```sh
npm run local:start
npm run local:status
npm run local:stop
```

## 后续通过对话修改

告诉 Codex「修改 musical-puppy-local 的……」或「修改门户后台本地预览的……」，描述具体页面和希望的变化即可。每次修改编辑副本，重新构建后刷新同一个预览地址。

目录用途：

- `source/`：原站原始快照，保留作对照，不在这里做升级。
- `app/`：后续对话编辑的工作目录；入口为 `app/index.html`，业务脚本和样式位于 `app/assets/`。
- `dist/`：服务实际读取的预览目录，由构建命令完整同步；不要直接编辑，以免下次构建覆盖。
- `RESOURCE-MANIFEST.json`：原始资源的来源、大小、SHA-256 和采集记录。
- `evidence/`：本次浏览器检查记录和截图。
- `.local-preview/`：本机进程状态和日志，不属于站点内容。

```sh
npm run build          # 将 app 完整同步到 dist
npm run check          # 原始快照、语法、编辑稿与预览稿一致性
npm run verify:http    # 服务运行时逐个验证资源、MIME、404、健康检查
npm run verify:origin  # 判断编辑版目前是否仍与原站快照逐字节相同
```

编辑后 `verify:origin` 报告差异是正常现象；`check` 仍应通过。当前工程无需安装依赖，使用本机 Node.js 18+ 和 Python 3（仅资源采集工具使用 Python）。

## 统一下拉组件

下拉框的视觉、选中态、键盘操作和箭头联动统一维护在 `app/assets/shared-select.js`，沿用原站图一对应的 GKX 样式，局部适配在 `app/assets/shared-select.css`。原有单选、多选入口以及 13 处旧原生下拉调用均已接入；包含资源编辑、组织/父页面级联、论文/专利/期刊字段、表单预览与分页。

后续新增同类控件请复用公共组件。`npm run check` 会检测重新引入的原生下拉调用，提示统一修正。现有业务校验和示例数据仍由各页面负责。

## 统一禁用与只读状态

禁用和锁定字段的公共样式位于 `app/assets/shared-disabled.css`，在入口最后加载，统一灰底、清晰文字、边框、占位文字和鼠标反馈，同时覆盖悬停、按下及焦点状态。普通禁用按钮、浅蓝禁用主按钮、透明文字操作和分页保留各自的控件形态。

真正禁用继续使用原生 `disabled` 或已有 `aria-disabled` 业务拦截；只读字段保留选择、复制和键盘定位。不要把人才库目录的业务状态 `.is-disabled` 当作不可点击控件，也不要用 `pointer-events:none` 统一封锁只读字段或禁用原因提示。

## 统一搜索区域与资源编号

搜索输入和查询/重置操作统一维护在 `app/assets/shared-search.js` 与 `shared-search.css`，复用原有 GKX 按钮。列表、日志、审核与候选弹窗共用输入规格、主查询按钮、描边重置按钮、焦点反馈和键盘处理；页面各自的查询与重置回调仍由原业务组件维护。期刊、专利的行编辑/删除直接定位当前记录。

资源选择弹窗的编号使用普通正文元素，由 `app/assets/resource-picker.css` 保持与同一行名称一致的颜色和字体，不再作为蓝色等宽代码显示。Token、接口示例等真实代码内容继续保留代码样式。

## 保留范围和能力边界

12 个主菜单页面均在已下载业务脚本中：报告管理、公告管理、流程中心、表单中心、评论审核、埋点信息管理、埋点数据统计、用户管理、角色管理、页面管理、资源管理、权限配置。

已保留原站布局、文案、内置演示数据、交互、图片、图标、样式内嵌 SVG 及 Netlify 角标。CSS 未引用额外字体文件；使用设备现有字体。页面切换依靠前端状态，当前页面可由浏览器本地存储恢复。

本地地址与原站地址属于不同站点，各自的浏览器数据互不共享。复制部署文件不会复制原站浏览器中个人编辑过的本地数据。

公开产物未提供 source map 引用，本目录保留的是已编译可运行前端，不能据此称为恢复了原始 React/TypeScript 开发工程。可继续编辑现有 JS/CSS/HTML，较大的升级可在保留快照的前提下逐步整理组件。

原站自身的原型边界也被原样保留：

- 组织和用户对接地址是示例占位地址，连接测试、同步等行为由前端模拟；未发现业务接口请求。
- 上传操作读取文件名，不上传、解析或持久保存文件内容。
- 示例 PDF 名称为页面数据及占位预览，没有真实 PDF 下载源，不能作为已下载文档使用。
- 公告数据有浏览器本地存储；许多其他管理操作仅保存在当前页面内存，刷新可能恢复初始数据。不能将其作为真实权限、数据库或后台管理服务使用。
- 用户将来输入外部封面地址等内容时，仍可能引用相应远程资源；初始页面所引用的静态资源均已下载。

资源完整性以公开页面实际引用且可获取的内容为边界；站点未公开的原始工程、后台数据库、未链接文件不在本次可下载范围内。

原 Netlify 站点未改动，编辑版单独发布在上述 GitHub Pages 地址。后续本地编辑延用本目录和固定端口。
## 结构化资源弹窗维护

论文、专利、期刊分别由 `paper-editor.js`、`patent-editor.js`、`journal-editor.js` 维护呈现，共用 `resource-editor.css` 和 `resource-dialog.js` 的 640px 弹窗、24px 内距、上方标签、8/16px 间距、32px 控件、分组和焦点规则。参考 Figma 页面 `304:172` 的对应编辑节点；原稿图标位于 `app/assets/paper-editor/`。

`shared-date.js` 与共享下拉统一日期/枚举交互；选择弹层先响应 Esc，主弹窗负责 Tab 循环和回焦。新增同类资源弹窗复用这些组件，不再复制独立样式。保存行时附带完整 `_resourceDraft`，保证当前前端会话中的复杂字段能重新打开；刷新仍遵循原型的内存数据边界。

### 作者与机构选择器演示

`app/assets/resource-picker.js` 为公共选择弹窗，复用既有搜索和按钮；`resource-picker-demo.js` 提供本地模拟候选数据。作者 12 条、机构 8 条，作者支持跨页多选与批量回填，机构按每张作者卡的单值字段选择。界面不显示演示备注，数据来源仍为本地。`resource-candidate.css` 管理弹窗样式，`shared-toolbar.css` 统一首行工具栏的顶部对齐，覆盖报告、智库及其他同类布局。

### 表格省略内容的公共交互

`app/assets/table-overflow.js/css` 统一表格全文提示，由入口安装一次。覆盖手动省略的 `data-overflow-text`、实际被列宽裁切的普通单元格、选择弹窗和自定义内容列；支持悬停、键盘聚焦、移入阅读与选字，滚动、页面切换或关闭时清理。仅读取当前可见 DOM 文本或显式全文，不读取行数据或输入值；Token、操作按钮和选择控件不参与。

### 共用输入清空与字段布局

清空图形按 Figma 输入框中的 16px 实例显示，保留 24px 点击范围；数字输入共用 `is-number` 后缀布局，清空在左、原生加减箭头在最右，文字保留足够空间。无需为每张表单单独调整。

`shared-input.js/css` 提供共用清空按钮，搜索与日期控件复用同一按钮。图标采用 Figma 原生 SVG 导出；输入有值时悬停或聚焦显示，触摸环境有值时常显（CSS 实现检查），空值、只读和禁用字段不显示。清空沿用原 React 事件并回焦，日期保留日历入口，公告的原生日期时间输入保留时间部分。全局单选输入共用同一套 16px 选中/未选中图形，不改变业务选择逻辑。

目录及同类表单的单字段占满整行，双字段等宽；专利文献种类同步占满整行。已验证桌面与 390×844 窄视口布局、专利文本/日期清空、论文只读 ID、期刊影响因子保存重开及人才搜索清空，详情见 `VERIFICATION.md`。本轮资源保存重开仅在当前前端会话内验证，没有后端持久化。
